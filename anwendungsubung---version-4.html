    Wir werden die Elemente aus Version 3 des Abschnitts „Link“ übernehmen und sie so anpassen, dass sie der neuen Architektur der Anwendung entsprechen.     Die Klasse [Utilitaires] enthält nützliche Methoden zur Verwaltung von Textdateien (hier eine einzige Methode):

    
<?php

// Namensraum
namespace Application;

// Eine Klasse mit Hilfsfunktionen
abstract class Utilitaires {

  public static function cutNewLinechar(string $ligne): string {
    // Die Zeilenende-Markierung von $ligne wird entfernt, falls vorhanden
    $longueur = strlen($ligne);  // Zeilenlänge
    while (substr($ligne, $longueur - 1, 1) == "\n" or substr($ligne, $longueur - 1, 1) == "\r") {
      $ligne = substr($ligne, 0, $longueur - 1);
      $longueur--;
    }
    // Ende – die Zeile wird zurückgegeben
    return($ligne);
  }
}

    11.3. Die Schicht [dao]

    Wir befassen uns hier mit der Schicht [1] unserer Anwendung:

    11.3.1. Die Schnittstelle [InterfaceDao]

    Die Schnittstelle der Schicht [dao] lautet wie folgt: [InterfaceDao.php]:

    
<?php

// Namensraum
namespace Application;

interface InterfaceDao {

  // Auslesen der Steuerzahlerdaten
  public function getTaxPayersData(string $taxPayersFilename, string $errorsFilename): array;

  // Auslesen der Daten der Steuerbehörde (Steuerklassen)
  public function getTaxAdminData(): TaxAdminData;

  // Speichern der Ergebnisse
  public function saveResults(string $resultsFilename, array $taxPayersData): void;
}

    Anmerkungen

    • Die Anforderungen lauten wie folgt:
      • Die Daten der Steuerzahler befinden sich in einer Textdatei;
      • die Ergebnisse der Steuerberechnung werden in einer Textdatei gespeichert;
      • Eventuelle Fehler werden in einer Textdatei protokolliert;
      • es ist nicht bekannt, in welchem Format die Daten der Steuerbehörde vorliegen. Für jedes neue Format muss die Schnittstelle [InterfaceDao] durch eine neue Klasse implementiert werden;
      • Die Methoden der Schnittstelle, bei denen beim Zugriff auf die Daten ein nicht behebbarer Fehler auftritt, müssen eine Ausnahme vom Typ [ExceptionImpots] auslösen;
    • Zeile 9: Die Methode zum Abrufen der Steuerzahlerdaten [statut marital, nombre d’enfants, salaire annuel];
      • Der erste Parameter ist der Name der Textdatei, in der sich diese Daten befinden;
      • Der zweite Parameter ist der Name der Textdatei, in der eventuell aufgetretene Fehler gespeichert werden sollen;
    • Zeile 12: Die Methode zum Abrufen der Daten der Steuerbehörde. Hier werden keine Parameter übergeben, da nicht bekannt ist, wie diese Daten gespeichert sind;
    • Zeile 15: Die Methode, mit der die Ergebnisse der Steuerberechnung in einer Textdatei gespeichert werden, deren Name als Parameter übergeben wird;

    Beim Schreiben der Schnittstelle [InterfaceDao] ist bekannt, dass es je nach Art der Speicherung der Daten der Steuerbehörde verschiedene Möglichkeiten geben wird, die Methode [getTaxAdminData] zu implementieren. Die Schnittstelle [InterfaceDao] wird daher durch verschiedene Klassen implementiert, von denen jede für eine bestimmte Art der Speicherung dieser Daten zuständig ist (Tabellen, Textdateien, Datenbank, Webservice). Diese abgeleiteten Klassen werden jedoch einen gemeinsamen Code aufweisen, nämlich den der Implementierung der Methoden [getTaxPayersData, saveResults]. Es ist bekannt, dass dieser Anwendungsfall auf zwei Arten implementiert werden kann (siehe Abschnitt „Link“):

    1. Man erstellt eine abstrakte Klasse C, die den gemeinsamen Code der abgeleiteten Klassen zusammenfasst. Die Klasse C implementiert die Schnittstelle I, aber bestimmte Methoden, die in den abgeleiteten Klassen deklariert werden müssen, sind in der Klasse C als abstrakt deklariert, weshalb die Klasse C selbst abstrakt ist. Anschließend erstellt man die von C abgeleiteten Klassen C1 und C2, die jeweils auf ihre eigene Weise die nicht definierten (abstrakten) Methoden ihrer übergeordneten Klasse C implementieren;
    2. man erstellt ein Merkmal T, das nahezu identisch mit der abstrakten Klasse C aus der vorherigen Lösung ist. Dieses Merkmal implementiert die Schnittstelle I nicht, da es dies syntaktisch nicht kann. Anschließend werden die Klassen C1 und C2 erstellt, die die Schnittstelle I implementieren und das Trait T verwenden. Diese Klassen müssen lediglich die Methoden der Schnittstelle I implementieren, die nicht durch das von ihnen importierte Trait T implementiert werden;

    Für das Beispiel verwenden wir hier ein Trait [TraitDao].

    11.3.2. Das Trait [TraitDao]

    Der Code des Traits [TraitDao] lautet wie folgt: [TraitDao.php]:

    
<?php

// Namensraum
namespace Application;

trait TraitDao {

  // Lesen der Steuerpflichtigen-Daten
  public function getTaxPayersData(string $taxPayersFilename, string $errorsFilename): array {
    // Steuerpflichtigen-Tabelle
    $taxPayersData = [];
    // Fehlertabelle
    $errors = [];
    // Beim Verarbeiten von Dateien können zahlreiche Fehler auftreten
    try {
      // Einlesen der Benutzerdaten
      // Jede Zeile hat das Format: Familienstand, Anzahl der Kinder, Jahresgehalt
      $taxPayersFile = fopen($taxPayersFilename, "r");
      if (!$taxPayersFile) {
        throw new ExceptionImpots("Impossible d'ouvrir en lecture les déclarations des contribuables [$taxPayersFilename]", 12);
      }
      // Die aktuelle Zeile der Benutzerdatendatei wird ausgewertet
      // die das Format Familienstand, Anzahl der Kinder, Jahresgehalt hat
      $num = 1;         // aktuelle Zeilennummer
      $nbErreurs = 0;   // Anzahl der aufgetretenen Fehler
      while ($ligne = fgets($taxPayersFile, 100)) {
        // Leere Zeilen werden ignoriert
        $ligne = trim($ligne);
        if (strlen($ligne) == 0) {
          // nächste Zeile
          $num++;
          // Schleife wiederholen
          continue;
        }
        // Eventuelles Zeilenendezeichen wird entfernt
        $ligne = Utilitaires::cutNewLineChar($ligne);
        // die drei Felder „verheiratet:Kinder:Gehalt“ werden extrahiert, die $ligne bilden
        list($marié, $enfants, $salaire) = explode(",", $ligne);
        // man überprüft sie
        // Der Familienstand muss „Ja“ oder „Nein“ lauten
        $marié = trim(strtolower($marié));
        $erreur = ($marié !== "oui" and $marié !== "non");
        if (!$erreur) {
          // Die Anzahl der Kinder muss eine ganze Zahl sein
          $enfants = trim($enfants);
          if (!preg_match("/^\d+$/", $enfants)) {
            $erreur = TRUE;
          } else {
            $enfants = (int) $enfants;
          }
        }
        if (!$erreur) {
          // Das Gehalt ist eine ganze Zahl ohne Euro-Cent
          $salaire = trim($salaire);
          if (!preg_match("/^\d+$/", $salaire)) {
            $erreur = TRUE;
          } else {
            $salaire = (int) $salaire;
          }
        }
        // Fehler?
        if ($erreur) {
          $errors[] = "la ligne [$num] du fichier [$taxPayersFilename] est erronée";
          $nbErreurs++;
        } else {
          // Die Informationen werden gespeichert
          $taxPayersData[] = (new TaxPayerData())->setFromParameters($marié, $enfants, $salaire);
        }
        // nächste Zeile
        $num++;
      }
      // Sind wir am Ende der Datei angelangt?
      if (!feof($taxPayersFile)) {
        // Die Schleife wurde aufgrund eines Lesefehlers verlassen
        throw new ExceptionImpots("Erreur lors de la lecture de la ligne n° [$num] du fichier [$taxPayersFilename]");
      } else {
        // Die Schleife wurde aufgrund der Markierung für das Dateiende verlassen
        // Die Fehler werden in einer Textdatei gespeichert
        $this->saveString($errorsFilename, implode("\n", $errors));
        // Ergebnis der Funktion
        return $taxPayersData;
      }
    } finally {
      // Die Datei wird geschlossen, falls sie geöffnet ist
      if ($taxPayersFile) {
        fclose($taxPayersFile);
      }
    }
  }

  // Speichern der Ergebnisse
  public function saveResults(string $resultsFilename, array $taxPayersData): void {
    // Speichern des Arrays [$taxPayersData] in der Textdatei [$resultsFileName]
    // Wenn die Textdatei [$resultsFileName] nicht existiert, wird sie angelegt
    $this->saveString($resultsFilename, implode("\n", $taxPayersData));
  }

  // Speichern der Ergebnisse einer Tabelle in einer Textdatei
  private function saveString(string $fileName, string $data): void {
    // Speichern der Tabelle [$data] in der Textdatei [$fileName]
    // Wenn die Textdatei [$fileName] nicht existiert, wird sie angelegt
    if (file_put_contents($fileName, $data) === FALSE) {
      throw new ExceptionImpots("Erreur lors de l'enregistrement de données dans le fichier texte [$fileName]");
    }
  }

}

    Anmerkungen

    • Zeile 6: Wir definieren hier eine Eigenschaft und keine Klasse;
    • Zeilen 9–89: Die Methode [getTaxPayersData] implementiert die gleichnamige Methode der Schnittstelle [InterfaceDao]. Sie ruft aus einer Textdatei namens [$taxPayersFilename] die Daten der Steuerzahler [statut marital, nombre d’enfants, salaire annuel] ab. Sie gibt diese in Form eines Arrays [$taxPayersData] mit Elementen vom Typ [TaxPayerData] zurück (Zeilen 67, 81);
    • Die Methode [getTaxPayersData] ist der im Abschnitt „Link“ beschriebenen Methode [AbstractBaseImpots::executeBatchImpots] sehr ähnlich, weist jedoch folgende Unterschiede auf:
      • Die Methode [getTaxPayersData] ruft lediglich die Daten der Steuerzahler ab. Sie führt keine Steuerberechnung durch. Dies ist die Aufgabe der Ebene [métier];
      • Wie bereits die Methode [executeBatchImpots] meldet sie Fehler. Hier werden die Fehler zunächst in einem Array [$errors] (Zeile 13) gespeichert, das am Ende der Verarbeitung in eine Textdatei geschrieben wird (Zeile 79). Je nach Fall ist es leer oder nicht;
      • Im Falle eines nicht behebbaren Fehlers wird eine Ausnahme vom Typ [ExceptionImpots] ausgelöst (Zeilen 20, 75);
    • Zeile 73: Zu beachten ist die Verarbeitung nach dem Verlassen der Schleife der Zeilen 26–71. Tatsächlich hat die Funktion [fgets] den Nachteil, dass sie den Booleschen Wert FALSE sowohl dann zurückgibt, wenn beim Einlesen der Zeilen die Dateiende-Markierung erreicht wurde, als auch dann, wenn das Einlesen aufgrund eines Fehlers nicht erfolgreich war. Um zwischen diesen beiden Fällen zu unterscheiden, wird mit der Funktion [feof] geprüft, ob das Dateiende erreicht wurde. Ist das Dateiende noch nicht erreicht, liegt ein Fehler vor, und es wird eine Ausnahme ausgelöst;
    • Zeilen 83–88: [finally] wird ausgeführt, unabhängig davon, ob bei der Verarbeitung der Datei eine Ausnahme aufgetreten ist oder nicht;
    • Zeile 85: Wenn die Datei geöffnet wurde, hat das „Handle“ [$taxPayersFile] der Datei den booleschen Wert TRUE, andernfalls FALSE;
    • Zeilen 99–105: Die private Methode [saveString], die in Zeile 79 verwendet wurde, um das Fehlerarray in einer Textdatei zu speichern;
    • Zeile 99: Die Methode [saveString] erhält zwei Parameter:
      • [string $filename], den Namen der Textdatei, in die die Daten gespeichert werden sollen;
      • [string $data], die Zeichenkette, die in die Textdatei geschrieben werden soll. Diese Zeichenkette besteht aus einer Reihe von Zeilen, die jeweils mit dem Zeilenendezeichen \n enden;
    • Zeile 102: Die Funktion PHP [file_puts_contents] schreibt eine Zeichenkette in eine Textdatei. Sie öffnet die Datei, schreibt die Zeichenfolge hinein und schließt die Datei wieder. Sie gibt den Booleschen Wert FALSE zurück, falls ein Fehler aufgetreten ist;
    • Zeile 103: Wenn ein Fehler auftritt, wird eine Ausnahme ausgelöst;
    • Zeilen 92–96: Implementierung der Methode [saveResults] der Schnittstelle [InterfaceDao]. Dabei wird erneut die private Methode [saveString] verwendet. Hier ist der zweite Parameter von [saveString] eine Zeichenkette, die aus dem Array [$taxPayersData] gebildet wird, dessen Elemente vom Typ [TaxPayerData] sind. Man kann sich fragen, wie das Ergebnis der Operation aussehen wird: 
    
implode("\n", $taxPayersData)

    Wir haben in der Klasse [TaxPayerData] (Absatz „Link“) die folgende Methode [__toString] definiert:

    
public function __toString() {
    // JSON-Zeichenkette des Objekts
    return \json_encode(\get_object_vars($this), JSON_UNESCAPED_UNICODE);
  }

    Die Operation

    
implode("\n", $taxPayersData)

    verkettet jedes Element des Arrays [$taxPayersData], das durch dessen Methode [__toString] in eine Zeichenkette umgewandelt wurde, mit dem Zeilenendezeichen \n. Dies ergibt eine Zeichenkette der Form:

    json1\njson2\n…

    Fazit

    Die Eigenschaft [TraitDao] hat zwei der Methoden der Schnittstelle [InterfaceDao] implementiert, nämlich [getTaxPayersData] und [saveResults]:

    
<?php

// Namensraum
namespace Application;

interface InterfaceDao {

  // Auslesen der Steuerpflichtigen-Daten
  public function getTaxPayersData(string $taxPayersFilename, string $errorsFilename): array;

  // Auslesen der Daten der Steuerbehörde (Steuerklassen)
  public function getTaxAdminData(): TaxAdminData;

  // Speichern der Ergebnisse
  public function saveResults(string $resultsFilename, array $taxPayersData): void;
}

    Nun müssen wir noch die Methode [getTaxAdminData] implementieren, die die Daten der Steuerbehörde abruft.

    • Zeile 9: Die Klasse [ImpotsWithTaxAdminDataInJsonFile] verwendet das Merkmal [traitDao], von dem bekannt ist, dass es die Methoden [getTaxPayersData] und [saveResults] derSchnittstelle [InterfaceDao] implementiert. Somit muss die Klasse [ImpotsWithTaxAdminDataInJsonFile] nur noch die Methode [getTaxAdminData] implementieren, die die Daten der Steuerbehörde abruft;
    • Zeile 11: das Attribut vom Typ [TaxAdminData], das von der Methode [getTaxAdminData] der Zeilen 20–22 zurückgegeben wird. Dieses Attribut wird vom Konstruktor der Zeilen 14–17 initialisiert;

    Wir sind mit der Schicht [dao] unserer Anwendung fertig: Wir haben nun eine Klasse, die die von uns festgelegte Schnittstelle [InterfaceDao] vollständig implementiert. Wir können nun zur Schicht [métier] übergehen.

    11.4. Die Schicht [métier]

    Wir werden nun die Schicht [2] unserer Architektur implementieren:

    11.4.1. Die Schnittstelle [InterfaceMétier]

    Die Schnittstelle der Schicht [métier] sieht wie folgt aus:

    
<?php

// Namensraum
namespace Application;

interface InterfaceMetier {

  // Berechnung der Steuern eines Steuerpflichtigen
  public function calculerImpot(string $marié, int $enfants, int $salaire): array;

  // Steuerberechnung im Batch-Modus
  public function executeBatchImpots(string $taxPayersFileName, string $resultsFileName, string $errorsFileName): void;
}

    Anmerkungen

    • Zeile 9: Die Schnittstelle [InterfaceMétier] kann den Steuerbetrag eines bestimmten Steuerpflichtigen berechnen, sofern folgende Informationen vorliegen: Familienstand, Anzahl der Kinder, Jahresgehalt. Die Methode [calculerImpot] nutzt die Schicht [dao] nicht und löst daher keine Ausnahmen aus;
    • Zeile 9: Die Schnittstelle [InterfaceMétier] kann ebenfalls den Steuerbetrag für eine Gruppe von Steuerzahlern berechnen, deren Daten in der Textdatei mit dem Namen [$taxPayersFileName] zusammengefasst sind. Sie speichert die Ergebnisse in einer Textdatei mit dem Namen [$resultsFileName]. Die Methode [executeBatchImpots] muss die Schicht [dao] ansprechen, die für den Zugriff auf das Dateisystem zuständig ist. Ausnahmen können dann von der Schicht [dao] weitergeleitet werden, die von der Methode [executeBatchImpots] nicht abgefangen werden: Sie lässt sie an das Hauptskript weiterleiten. Nicht schwerwiegende Fehler werden in der Textdatei mit dem Namen [$errorsFileName] protokolliert;
    • Zeile 9: Die Methode [calculerImpot] ist eine reine [métier]-Methode. Sie kümmert sich nicht darum, woher die von ihr verwendeten Daten stammen;
    • Zeile 12: Die Methode [executeBatchImpots] wendet sich an die Schicht [dao], um Daten aus Textdateien zu lesen und in diese zu schreiben. Sie ruft wiederholt die Geschäftslogik-Methode [calculerImpot] auf;

    11.4.2. Die Klasse [Metier]

    Die Klasse [Metier] implementiert die Schnittstelle [InterfaceMetier] wie folgt:

    
<?php

// Namensraum
namespace Application;

class Metier implements InterfaceMetier {
  // Dao-Ebene
  private $dao;
  // Daten der Steuerverwaltung
  private $taxAdminData;

  //---------------------------------------------
  // Setter der Schicht [dao]
  public function setDao(InterfaceDao $dao) {
    $this->dao = $dao;
    return $this;
  }

  public function __construct(InterfaceDao $dao) {
    // Es wird eine Referenz auf die Schicht [dao] gespeichert
    $this->dao = $dao;
    // Die Daten für die Steuerberechnung werden abgerufen

public function calculerImpot(string $marié, int $enfants, int $salaire): array {
    // $marié: ja, nein
    // $enfants: Anzahl der Kinder
    // $salaire: Jahresgehalt
    // $this->taxAdminData: Daten der Steuerbehörde
    //
    // Es wird überprüft, ob die Daten der Steuerbehörde vorliegen
    if ($this->taxAdminData === NULL) {
      $this->taxAdminData = $this->getTaxAdminData();
    }
    // Steuerberechnung mit Kindern
    $result1 = $this->calculerImpot2($marié, $enfants, $salaire);
    $impot1 = $result1["impôt"];
    // Berechnung der Steuer ohne Kinder
    if ($enfants != 0) {
      $result2 = $this->calculerImpot2($marié, 0, $salaire);
      $impot2 = $result2["impôt"];
      // Anwendung der Obergrenze für den Familienquotienten
      $plafonDemiPart = $this->taxAdminData->getPlafondQfDemiPart();
      if ($enfants < 3) {
        // $PLAFOND_QF_DEMI_PART Euro für die ersten beiden Kinder
        $impot2 = $impot2 - $enfants * $plafonDemiPart;
      } else {
        // $PLAFOND_QF_DEMI_PART Euro für die ersten beiden Kinder, das Doppelte für die folgenden
        $impot2 = $impot2 - 2 * $plafonDemiPart - ($enfants - 2) * 2 * $plafonDemiPart;
      }
    } else {
      $impot2 = $impot1;
      $result2 = $result1;
    }
    // es gilt der höhere Steuersatz
    if ($impot1 > $impot2) {
      $impot = $impot1;
      $taux = $result1["taux"];
      $surcôte = $result1["surcôte"];
    } else {
      $surcôte = $impot2 - $impot1 + $result2["surcôte"];
      $impot = $impot2;
      $taux = $result2["taux"];
    }
    // Berechnung eines eventuellen Steuerabzugs
    $décôte = $this->getDecôte($marié, $salaire, $impot);
    $impot -= $décôte;
    // Berechnung einer möglichen Steuerermäßigung
    $réduction = $this->getRéduction($marié, $salaire, $enfants, $impot);
    $impot -= $réduction;

    11.7. Tests [Codeception]

    Die visuellen Tests sind völlig unzureichend:

    • Man beschränkt sich in der Regel auf wenige Tests;
    • man ist bei dieser visuellen Überprüfung mehr oder weniger aufmerksam, und Details können uns entgehen;

    In der Praxis der professionellen Softwareentwicklung werden Tests von spezialisierten Mitarbeitern erstellt, für die dies die Hauptaufgabe ist. Sie sind bestrebt, die Tests so umfassend wie möglich zu gestalten. Dazu nutzen sie Test-Frameworks.

    Wir werden hier das Framework Codeception [https://codeception.com/] verwenden, da es in NetBeans integriert werden kann. Es handelt sich um ein Framework mit einem breiten Spektrum an Möglichkeiten. Wir werden jedoch nur einige davon nutzen. Die Idee dahinter ist, nach jeder neuen Version der Anwendungsübung schnell überprüfen zu können, ob diese funktioniert. Erfolgreiche Tests geben dem Entwickler Vertrauen in den von ihm geschriebenen Code. Das ist ein wichtiger Faktor.
