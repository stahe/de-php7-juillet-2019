    5. Klassen

    Begriffserklärung: Eine Klasse (class) ist ein Typ PHP. Eine Variable dieses Typs wird als Objekt bezeichnet. Ein Objekt ist eine Instanz (ein Exemplar) einer Klasse.

    5.2. Jede Variable kann zu einem Objekt mit Attributen werden

    Das Skript [classes-01.php] lautet wie folgt:

    
<?php

// ein generisches Objekt
// $obj1=new stdClass();
// Jede Variable kann per Definition Attribute haben
$obj1->attr1 = "un";

// ändert das Objekt
$obj1->attr2 += 100;
// zeigt das Objekt an
print "objet1=[$obj1->attr1,$obj1->attr2]\n";
// kopiert den Wert von Objekt1 (Adresse des referenzierten Objekts) in Objekt2
// Die beiden Variablen sind nun unterschiedlich, verweisen aber auf dasselbe Objekt
$obj2 = $obj1;
// ändert obj2
$obj2->attr2 = 0;
// zeigt die beiden Objekte an
print "objet1=[$obj1->attr1,$obj1->attr2]\n";
print "objet2=[$obj2->attr1,$obj2->attr2]\n";
// ändert das Objekt, auf das „Objekt1“ verweist
$obj1 = new stdClass();

}

    • Zeile 6: Die Notation $obj->attr bezeichnet das Attribut attr der Variablen $obj. Falls dieses nicht existiert, wird es erstellt, wodurch die Variable $obj zu einem Objekt mit Attributen wird. Wir haben gesehen, dass PHP dann standardmäßig ein Objekt vom Typ stdClass erstellt;
    • Zeile 16: Der Ausdruck $obj2=$obj1 ist, sofern $obj1 ein Objekt ist, eine Kopie von Objekten per Referenz: $obj2 und $obj1 sind Referenzen (Adressen) auf dasselbe Objekt. Das Objekt selbst kann durch die eine oder die andere Referenz geändert werden;
    • Zeilen 23–27: sollen zeigen, dass $obj1 und $obj2 zwei verschiedene Variablen sind: Sie befinden sich nicht an derselben Speicheradresse:
      • $obj2=$obj1 hat den Wert von $obj1 in die Variable $obj2 kopiert (Schritt 1 oben). Der Wert von $obj1 ist die Adresse eines Objekts. Somit verweisen $obj1 und $obj2 auf dasselbe Objekt. Wenn man eine Variable $obj bearbeitet und diese auf ein Objekt verweist, bearbeitet PHP das Objekt, auf das die Variable $obj verweist. Aus dem folgenden Schema geht hervor, dass das Objekt, auf das verwiesen wird, entweder über $obj1 oder über $obj2 geändert werden kann. Dies zeigen die Zeilen 4 und 5 der Ergebnisse;

    • Zeile 30: Der Ausdruck $obj3=&$obj2 bewirkt, dass $obj2 und $obj3 dieselbe Adresse haben wie [1 ci-dessous]. Man könnte sagen, dass die beiden Variablen Aliase desselben Speicherplatzes sind. Sie verweisen beide auf ein Objekt, Objekt A, im folgenden Beispiel [2];
      • die Operation $obj2=new stdClass() bewirkt, dass ein neues Objekt, Objekt B ([3 ci-dessous]), erstellt wird und die Adresse dieses neuen Objekts der Variablen $obj2 zugewiesen wird. Da $obj2 und $obj3 zwei Aliase für denselben Speicherort sind, verweist auch $obj3 auf das neue Objekt „Objekt B“. Dies geht aus den Zeilen 16–27 und 30–41 der Ergebnisse hervor;

    • Zeilen 52–54: zeigen, dass ein Objekt wie ein Wörterbuch durchlaufen werden kann. Die Schlüssel des Wörterbuchs sind die Namen der Attribute und die Werte des Wörterbuchs die Werte eben dieser Attribute;
    • Zeile 51: Die Funktion count kann auf ein Objekt angewendet werden (mit einer Warnung), gibt jedoch nicht, wie man erwarten könnte, die Anzahl der Attribute zurück. Ein Objekt weist also Ähnlichkeiten mit einem Wörterbuch auf, ist aber keines;

    5.3. Eine Klasse „Person“ ohne deklarierte Attribute

    Das Skript [classes-02.php] lautet wie folgt:

    
<?php

class Personne {

  // Attribute der Klasse
  // nicht deklariert – können dynamisch erstellt werden
  // Methode
  function identite() {
    // verwendet a priori nicht vorhandene Attribute
    return "[$this->prenom,$this->nom,$this->age]";
  }

}

// Test
// Die Attribute sind öffentlich und können dynamisch erstellt werden
$p = new Personne();
$p->prenom = "Paul";
$p->nom = "Langevin";
$p->age = 48;
// Aufruf einer Methode
print "personne=" . $p->identite() . "\n";
// Ende
exit;

    Kommentare

    • Zeilen 3–13: Definieren eine Klasse Personne. Eine Klasse ist eine Vorlage, anhand derer Objekte erstellt werden. Sie umfasst Attribute und Funktionen, die als Methoden bezeichnet werden. Es besteht keine Verpflichtung, die Attribute zu deklarieren;
    • Zeilen 8–11: Die Methode identité gibt den Wert von drei Attributen aus, die in der Klasse nicht deklariert sind. Das Schlüsselwort $this bezeichnet das Objekt, auf das die Methode angewendet wird;
    • Zeile 17: Es wird ein Objekt $p vom Typ Personne erstellt. Das Schlüsselwort „new“ dient dazu, ein neues Objekt zu erstellen. Der Vorgang gibt eine Referenz auf das erstellte Objekt zurück (also eine Adresse). Verschiedene Schreibweisen sind möglich: new Personne(), new Personne, new personne. Bei der Klasse wird die Groß-/Kleinschreibung nicht berücksichtigt;
    • Zeilen 18–20: Die drei für die Methode identité erforderlichen Attribute werden im Objekt $p angelegt;
    • Zeile 22: Die Methode identité der Klasse Personne wird auf das Objekt $p angewendet. Im Code (Zeilen 8–11) der Methode identité verweist $this auf dasselbe Objekt wie $p;

    5.5. Die Klasse „Person“ mit einem Konstruktor

    Die vorherigen Beispiele zeigten exotische Klassen wie Personne, wie sie in PHP 4 zu finden waren. Es wird nicht empfohlen, diesen Beispielen zu folgen. Wir stellen nun eine Klasse Personne [classes-04.php] vor, die den Best Practices von PHP 7 entspricht:

    
<?php

// Strikte Einhaltung der deklarierten Typen der Funktionsparameter
declare (strict_types=1);
class Personne {
// Attribute der Klasse
  private $prenom;
  private $nom;
  private $age;

// Getter und Setter
  public function getPrenom(): string {
    return $this->prenom;
  }

  public function getNom(): string {
    return $this->nom;
  }

  public function getAge(): int {
    return $this->age;
  }

  public function setPrenom(string $prenom): void {
    $this->prenom = $prenom;
  }

  public function setNom(string $nom): void {
    $this->nom = $nom;
  }

  public function setAge(int $age): void {
    $this->age = $age;
  }

// Konstruktor
  public function __construct(string $prenom, string $nom, int $age) {
    // man nutzt die Setter
    $this->setPrenom($prenom);
    $this->setNom($nom);
    $this->setAge($age);
  }

// Methode toString
  public function __toString(): string {
    return "[$this->prenom,$this->nom,$this->age]";
  }

}

// Test
// Anlegen eines Objekts vom Typ „Person“
$p = new Personne("Paul", "Langevin", 48);
// Identität dieser Person
print "personne=$p\n";
// Das Alter wird geändert
$p->setAge(14);
// Identität der Person
print "personne=$p\n";
// Ende
exit;

    Kommentare

    • Zeilen 6–50: die Klasse „Person“;
    • Zeilen 7–9: die privaten (private) Attribute der Klasse. Diese Attribute sind nur innerhalb der Klasse sichtbar. Weitere verwendbare Schlüsselwörter sind:
    • public: Macht das Attribut von außerhalb der Klasse sichtbar,
    • protected: macht das Attribut zu einem Attribut protégé, das innerhalb der Klasse und in von ihr abgeleiteten Klassen sichtbar ist;
    • Da die Attribute privat sind, kann von außerhalb der Klasse nicht auf sie zugegriffen werden. Daher kann der folgende Code nicht geschrieben werden: 
    1
2
    $p=new Personne() ;
$p->nom="Landru" ;

    Hier befinden wir uns außerhalb der Klasse Personne. Da das Attribut nom privat ist, ist Zeile 2 falsch. Um die privaten Felder des Objekts $p zu initialisieren, gibt es zwei Möglichkeiten:

    • die öffentlichen Methoden „set“ und „get“ (die Namen dieser Methoden können beliebig sein) aus den Zeilen 12–34 verwenden. Man könnte dann schreiben: 
    1
2
    $p=new Personne() ;
$p->setNom("Landru") ;
    • den Konstruktor in den Zeilen 37–42 verwenden. Dann schreibt man: 
    1
    $p=new Personne("Michel","Landru",44) ;

    Die obige Schreibweise ruft automatisch die Methode der Klasse Personne namens __construct auf;

    • Zeile 59: Diese Zeile gibt die Person $p in Form einer Zeichenkette aus. Dazu wird die Methode der Klasse Personne namens __toString (Zeilen 45–47) verwendet;
    • allen Methoden der Klasse (Funktionen) wurde das Schlüsselwort „public“ vorangestellt, das angibt, dass die Funktion außerhalb der Klasse sichtbar ist. Die anderen verwendbaren Schlüsselwörter sind, wie bei den Attributen und mit derselben Bedeutung, „private“ und „protected“. Ohne explizites Sichtbarkeitsattribut ist die Funktion implizit öffentlich sichtbar;

    5.6. Die Klasse „Person“ mit Gültigkeitsprüfungen im Konstruktor

    Der Konstruktor einer Klasse ist der richtige Ort, um zu überprüfen, ob die Initialisierungswerte des Objekts korrekt sind. Ein Objekt kann jedoch auch über seine Methoden set oder gleichwertige Methoden initialisiert werden. Um zu vermeiden, dass dieselben Überprüfungen an zwei verschiedenen Stellen erfolgen, können diese in die Methoden set integriert werden. Sollte sich ein Initialisierungswert eines Objekts als falsch erweisen, wird eine Ausnahme ausgelöst. Hier ein Beispiel.

    Zunächst wird die Definition der Klasse Personne in eine eigene Datei [Personne.php] verschoben:

    
<?php

// Strikte Einhaltung der deklarierten Typen der Funktionsparameter
declare (strict_types=1);

// Namensraum;
namespace Exemples;

// Klasse „Person“
class Personne {
// Attribute der Klasse
  private $prenom;
  private $nom;
  private $age;

// Getter und Setter
  public function getPrenom(): string {
    return $this->prenom;
  }

  public function getNom(): string {
    return $this->nom;
  }

  public function getAge(): int {
    return $this->age;
  }

  public function setPrenom(string $prénom): void {
    // Der Vorname darf nicht leer sein
    $prénom = trim($prénom);
    if ($prénom === "") {
      throw new \Exception("Le prénom doit être non vide");
    } else {
      $this->prenom = $prénom;
    }
  }

  public function setNom(string $nom): void {
    // Der Nachname darf nicht leer sein
    $nom = trim($nom);
    if ($nom === "") {
      throw new \Exception("Le nom doit être non vide");
    } else {
      $this->nom = $nom;
    }
  }

  public function setAge(int $âge): void {
    // Das Alter muss gültig sein
    if ($âge < 0) {
      throw new \Exception("L'âge doit être un entier positif ou nul");
    } else {
      $this->age = $âge;
    }
  }

// Konstruktor
  public function __construct(string $prenom, string $nom, int $age) {
    // Wir verwenden die Setter
    $this->setPrenom($prenom);
    $this->setNom($nom);
    $this->setAge($age);
  }

  // Methode
  public function initWithPersonne(Personne $p): void {
    // initialisiert das aktuelle Objekt mit einer Person $p
    $this->__construct($p->prenom, $p->nom, $p->age);
  }

  // Methode toString
  function __toString(): string {
    return "[$this->prenom,$this->nom,$this->age]";
  }

}

    Kommentare

    • Zeile 4: Es wird festgelegt, dass der Typ der Funktionsparameter bei der Deklaration eingehalten werden muss;
    • Zeile 7: Definiert einen Namensraum (Namespace). Der vollständige Name (man sagt qualifié) der Klasse Personne lautet dann \Exemples\Personne. Beachten Sie das Zeichen \, mit dem der qualifizierte Name beginnt: Man erhält dann einen qualifizierten Namen absolu. Fehlt dieses Zeichen, erhält man einen qualifizierten Namen relatif (relativ zum aktuellen Namensraum). Wenn also zwei Klassen A und B zum selben Namensraum E gehören, kann man im Code der Klasse A die Klasse B über die Notation relative B erreichen. Wenn die Klasse A zum Namensraum E1 und B zum Namensraum E2 gehört, wird B im Code von A über die Notation absolue \E2\ erreicht.B. Die Definition einer Klasse innerhalb eines Namensraums ist nicht zwingend erforderlich, aber NetBeans gibt eine Warnung aus, wenn dies nicht geschieht. Daher werden wir dies tun. Außerdem sollten die Namensräume der Dateistruktur entsprechen. So sollte sich die Klasse A im Namensraum E1 in einer Datei namens E1/A.php befinden. Dies ist zwar nicht zwingend erforderlich, aber auch hier gibt NetBeans eine Warnung aus, wenn man es nicht beachtet. Am Beispiel der Klasse [\Exemples\Personne] gibt NetBeans eine Warnung aus, da die Dateistruktur der Datei [Personne.php] [exemples/classes/Personne.php] lautet und somit nicht mit dem Namensraum übereinstimmt. Man darf die Verzeichnisstruktur nicht mit dem Namensraum verwechseln. Der vollqualifizierte Name einer Klasse verwendet einen Namensraum und hat nichts mit der Verzeichnisstruktur der Datei PHP der Klasse zu tun. Die Verknüpfung zwischen Verzeichnisstruktur und Namensraum ist optional und muss nicht beachtet werden, wie wir es hier getan haben;
    • Zeilen 12–14: die drei privaten Attribute der Klasse;
    • Zeilen 29–37: Initialisierung des Attributs prenom und Überprüfung des Initialisierungswerts;
    • Zeile 31: Die Funktion trim($chaine) entfernt die Leerzeichen am Anfang und am Ende von $chaine. Somit ist trim(„abcd “) die Zeichenkette „abcd“ und trim(„ “) die leere Zeichenkette;
    • Zeile 32: Ist der Vorname leer, wird eine Ausnahme ausgelöst (Zeile 33), andernfalls wird der Vorname gespeichert (Zeile 35). Um eine Ausnahme auszulösen, wurde hier die vordefinierte Klasse [Exception] verwendet. Hier muss zwingend der absolute Name „[\Exception]“ verwendet werden. Verwendet man hingegen den relativen Namen [Exception], so wird diese Klasse im aktuellen Namensraum gesucht, d. h. im Namensraum [Exemples] der Klasse Personne. Somit sucht der Interpreter PHP nach einer Klasse mit dem absoluten Namen [\Exemples\Exception], die nicht existiert;

    Anmerkungen

    • Zeile 7: Das Skript wird die Klasse [Personne] verwenden. Daher muss dem Interpreter PHP mitgeteilt werden, wo er die Definition dieser Klasse finden kann. Dies ist die Aufgabe der Anweisungen [include fichier] und [require fichier]. Hier wurde die Anweisung [include] verwendet. Der Unterschied zwischen den beiden Anweisungen besteht darin: Wenn die Anweisung [include fichier] beim Laden von [fichier] auf Fehler stößt, wird ein Fehler der Stufe [E_WARNING] ausgegeben, diedie Ausführung wird fortgesetzt, während [require] im gleichen Fall einen schwerwiegenden Fehler auslöst und die Ausführung des Skripts beendet wird. Für jede der beiden Anweisungen gibt es eine Variante: [include_once] und [require_once]. Diese beiden Varianten ermöglichen es, den Fall mehrerer Einbindungen derselben Datei zu handhaben. Man kann sich hier ein Projekt vorstellen, das aus mehreren Skripten PHP besteht, von denen mehrere auf die Klasse [Personne] verweisen. Ihre Ausführung führt dann dazu, dass die Datei [Personne.php] mehrfach eingebunden wird, was einen Fehler verursacht, da eine Klasse nicht zweimal definiert werden darf. Die Lösung besteht darin, die Varianten [_once] zu verwenden, die sicherstellen, dass die Datei nur einmal in das globale Skript des Projekts eingebunden wird;
    • Zeile 7: Die Konstante [__DIR__] ist eine Konstante PHP, die den vollständigen Namen des Ordners angibt, in dem sich das Skript befindet, das die Konstante [__DIR__] enthält. Somit lautet der Ausdruck in Zeile 17: 
    
require_once __DIR__."/Personne.php";

    entspricht in etwa:

    
require_once ‘C:\Data\st-2019\dev\php7\php5-exemples\exemples\classes/Personnes.php’

    Im Dateipfad können die Zeichen / und \ beliebig verwendet werden;

    • Zeile 14: Hier wird die soeben definierte Klasse [Personne] verwendet. Das Skript [classes-05.php] hat keinen Namespace. In Zeile 14 wird der relative Name der Klasse [Personne] ohne Namespace verwendet. Da für die Klasse [Personne] kein Namensraum vorhanden ist, wird sie im Skript [classes-05.php] selbst gesucht und daher nicht gefunden. Es gibt zwei Lösungen für dieses Problem:
      • Verwenden Sie den vollständigen Namen der Klasse [\Exemples\Personne];

    5.14. Abstrakte Klassen

    Eine abstrakte Klasse ist eine unvollständige Klasse, die nicht instanziiert werden kann. Sie muss zwingend abgeleitet werden, um verwendet werden zu können.

    Wozu dient eine abstrakte Klasse? Manchmal gibt es Klassen, die eine oder mehrere Methoden gemeinsam haben, sich aber durch andere Methoden oder Attribute unterscheiden. In diesem Fall ist es sinnvoll, alle gemeinsamen Elemente in einer übergeordneten Klasse zusammenzufassen. Derzeit benötigen wir keine abstrakte Klasse. Nehmen wir jedoch an, die Unterklassen unterscheiden sich nur durch eine Methode M: Die Signatur der Methode wäre in allen Unterklassen gleich, ihre Implementierung würde sich jedoch unterscheiden. Um die Unterklassen zu verpflichten, die Methode M zu implementieren:

    • deklarieren wir die Signatur der Methode M in der übergeordneten Klasse. Da diese nicht weiß, wie sie die Methode implementieren soll, versehen wir die Methode mit dem Schlüsselwort „abstract“: Das bedeutet, dass die Implementierung der Methode M auf die untergeordneten Klassen verlagert wird;
    • da die übergeordnete Klasse nicht vollständig implementiert ist, wird sie ebenfalls mit demselben Schlüsselwort „abstract“ als abstrakt deklariert. Dadurch kann die Klasse nicht mehr instanziiert werden. Es muss zwingend eine Unterklasse erstellt werden, die die Implementierung der Methode M definiert, damit der Körper der übergeordneten Klasse nutzbar ist;

    Hier ein Beispiel: [classes-15.php]:

    
<?php

// strikter Einhaltung des Typs der Funktionsparameter
declare(strict_types=1);

// abstrakte Hauptklasse
abstract Class Classe1 {

  // Methode, die allen abgeleiteten Klassen bekannt ist
  public function f(): int {
    return 1;
  }

  // abstrakte Methode g – wird von den abgeleiteten Klassen definiert
  abstract function g(): int;
}

// abgeleitete Klasse
Class Classe2 extends Classe1 {

  // Die Methode „g“ der übergeordneten Klasse muss definiert werden
  public function g(): int {
    return parent::f() + 10;
  }

}

// abgeleitete Klasse
Class Classe3 extends Classe1 {

  // Die Methode g der übergeordneten Klasse muss definiert sein
  public function g(): int {
    return parent::f() + 20;
  }

  // Die Methode f der übergeordneten Klasse kann neu definiert werden
  public function f(): int {
    return 2;
  }

}

// Code
$c2 = new Classe2();
print $c2->f() . "\n";
print $c2->g() . "\n";
$c3 = new Classe3();
print $c3->f() . "\n";
print $c3->g() . "\n";

    5.17. Statische Methoden und Attribute

    5.19. jSON-Kodierung einer Klasse

    In einer Klasse ist häufig die Methode [__toString] vorhanden: Sie soll eine Zeichenkette zurückgeben, die das Objekt darstellt, das sie aufruft. Es mag verlockend sein, diese Zeichenkette als jSON zu definieren. Diesen Ansatz untersuchen wir nun.

    Wir verwenden die folgende Klasse „[Personne]“:

    
<?php

class Personne {
  // Attribute
  private $nom;
  private $prénom;
  private $âge;
  private $enfants;

  // globaler Setter
  public function setFromArray(array $arrayOfAttributes): Personne {
    // Initialisierung bestimmter Attribute der Klasse
    foreach ($arrayOfAttributes as $attribute => $value) {
      $this->$attribute = $value;
    }
    // Das Objekt wird zurückgegeben
    return $this;
  }

  // Getter
  public function getNom() {
    return $this->nom;
  }

  public function getPrénom() {
    return $this->prénom;
  }

  public function getÂge() {
    return $this->âge;
  }

  public function getEnfants() {
    return $this->enfants;
  }

  // __toString
  public function __toString(): string {
    // Das Objekt wird identifiziert
    var_dump($this);
    // seine Attribute werden abgerufen
    $attributes = \get_object_vars($this);
    var_dump($attributes);
    // die Zeichenkette jSON der Attribute wird zurückgegeben
    return \json_encode($attributes, JSON_UNESCAPED_UNICODE);
  }

}

  // Attribute
  private $nom;
  private $prénom;
  private $âge;

  // globaler Setter

  …

  public function __toString(): string {
    // Die Zeichenkette JSON der Attribute wird zurückgegeben
    $attributes = [];
    $this->getRecursiveAttributes($attributes, $this, []);
    // Zeichenkette JSON der Attribute
    return \json_encode($attributes, JSON_UNESCAPED_UNICODE);
  }

  public function getAttributes(): array {
    return \get_object_vars($this);
  }

  private function getRecursiveAttributes(array &$attributes, $value, $keys): void {
    // Analyse des Werts [$value]
    // $keys ist ein Array [key1, key2, .., keyn]
    // $value=$attributesQZXW2HTMLBW2tleTFdZQXQZXW2HTMLBW2tleTJdZQX….[keyn]
    // Wenn [$value] ein Objekt ist, verwendet man dessen Methode [getAttributes]
    if (\is_object($value)) {
      // Attribute des Objekts [$value]
      $objectAttributes = $value->getAttributes();
      // Was macht man mit dem Ergebnis?
      if ($keys) {
        // In [$attributes] ersetzen wir $value durch das Array seiner Attribute
        // Es muss das Element $attributesQZXW2HTMLBW2tleTFdZQXQZXW2HTMLBW2tleTJdZQX…[keyn] erstellt werden

        $attributes += $objectAttributes;
